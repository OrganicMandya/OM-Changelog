# Changelog

All notable changes to OM-Changelog, newest first. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/). **Every PR adds an entry under `[Unreleased]`.**

## [Unreleased]

### Changed
- **Moved the weekly auto-rebuild to Monday early morning.** The scheduled aggregation ran Wednesday 12:00 UTC; it now runs **Monday 00:30 UTC (≈ 06:00 IST)** so the page is fresh first thing at the start of the week. `deploy.yml` cron `0 12 * * 3` → `30 0 * * 1` (off the top-of-hour to avoid GitHub's cron congestion). Manual dispatch + `changelog-refresh` triggers unchanged. Also updated the on-page hero badge + "how this works" blurb in `generate.py`, which still read "every Wednesday".
- **Switched the auto-aggregator's rewrite model from Anthropic to OpenAI (`gpt-4o-mini`).** Per the CTO, the changelog reuses the OpenAI key the org already has rather than provisioning a new Anthropic one, so the go-live secret is now **`om/openai-api-key`** (was `om/anthropic-api-key`). `aggregate.py` calls the OpenAI SDK with **Structured Outputs** (`response_format` strict `json_schema`) — the optional `why` field is typed nullable so the strict schema (every property required) stays valid; `deploy.yml` installs `openai` and reads `om/openai-api-key` via the same OIDC path. Still fully **fail-open / dark** until the key is set in the vault — nothing on the live page changes on merge.
- **Added "Show more" pagination.** With 50+ entries the page was a long scroll, so it now reveals 15 updates at a time behind a **Show more** button (which shows how many are left). Works with the surface filter — picking a category resets to the first page — and the current "In testing / this week" items always show first. Pure client-side, no dependencies.
- **Expanded the changelog to a fuller set (22 → 50 entries) + added a scale line.** The 22-entry version still undersold the work — there were **~616 merged changes across the OM repos since June** (163 features, 121 fixes, plus security/perf), of which ~298 are user-facing. Curated **28 more** plain-language highlights spanning the app (secure connections, tamper-proof settings, full logout, redesigned Co-Op join, sort/filter, staged releases), staff tools (Report an Issue + tracking numbers, cron health monitor, faster/fresher dashboards, Microsoft SSO, CSV export, availability trend, role management, lost-sales metric, order-routing fixes), the live website (rotating announcements, cleaner cards, lighter pages, "not deliverable here" vs "sold out"), and stock (weekly catalog/lost-demand audit) — plus a one-line "in-testing" note for the Shopify-free storefront rebuild. Added a hero line — *"Since June we've shipped 600+ improvements … the updates below are the highlights"* — so the page reflects the true volume without becoming an unreadable dump. It stays curated highlights by design; the full 616 live in each repo's own history.
- **Backfilled the changelog history to 16 July 2026.** `content.json` had only 9 entries (23 Jul – 6 Aug), so the page looked like the product only started shipping in late July. Added 12 curated, plain-language highlights covering the earlier customer- and staff-facing wins (combos/bundles buyable again, hourly self-healing stock, stop-oversell-at-checkout, spoken order alerts, the org-wide Ticket Dashboard) and caught it up past 6 Aug (secure login storage, sensitive data out of logs, faster staff dashboards, PayU in testing, a leaner app, self-checking dashboards, instant wallet-history refresh). The page now spans **16 Jul → 11 Aug**. Note: OM's org repos were transferred/governed from mid-July, so genuine customer-facing shipped history begins there — the June–early-July period was foundational setup (testing, CI, safe-deploy pipelines), not user-visible shipping.
- **Rebuilt the page to the CTO's approved design + switched to a curated content source (OM-Infra#86).** Dark green hero, sticky client-side **surface filter**, updates grouped **In testing → Shipped this week → Earlier**, per-card surface/status badges, optional "Why it matters", and a REF chip. The generator now renders a curated **`content.json`** (plain-language entries) instead of scraping repo CHANGELOGs — the design's non-technical voice can't come from raw changelogs — which also **drops the cross-repo vault-token dependency**. Seeded with the approved sample entries. Weekly re-group + auto-draft-from-PRs (LLM) is the planned follow-up.

### Added
- **Org changelog page — generator + hosting (OM-Infra#86).** `generate.py` aggregates every repo's `CHANGELOG.md` into one plain-language, categorized page (App / Website / Staff tools / Stock & platform) with Shipped / In-testing status badges and auto-linked ticket refs; published to GitHub Pages (`changelog.organicmandya.club`) by `build-pages.yml` — weekly, on dispatch, and on a `changelog-refresh` ping. Falls back to the committed snapshot until the vault reader token is in place.
